AI Thinker ESP32-CAM · System blueprint

Overall control architecture

The ESP32-CAM runs its enabled transports concurrently. Angular/Node or Python chooses a client connection without changing firmware mode. Angular 21 uses zoneless signals; Node only starts listening at launch and does not open COM4 until the client requests a connection. The existing object-oriented firmware classes remain in place.

Blue: USB default/recovery Green: concurrent wireless services Purple: Angular-facing Node API and diagnostics

01 · USB stays available

USB-to-UART serial remains active whenever the board is running. Choose USB in the client to recover from a wireless connection failure; no firmware command or reboot is needed.

02 · Wireless interfaces coexist

The firmware starts Bluetooth SPP and, when configured, Wi-Fi TCP on port 3333 plus Wi-Fi HTTP on port 80. Python m tcp or the Angular selector changes the client link only. The ESP32 stores no mode selection.

03 · Shared camera logic

USB, TCP and Bluetooth invoke the same CommandProcessor; HTTP calls the same CameraController. Camera captures are serialized by the firmware main loop. The Angular interface uses one Node adapter at a time.

04 · Local Angular/Node pairing

Angular at localhost:4200 proxies /api to Node at 127.0.0.1:3000. Node handles COM ports, TCP and Bluetooth SPP. Startup opens only the HTTP listener; Angular makes no startup backend calls. Clicking Connect opens the selected client link. The device interfaces continue independently.

05 · Signals, status, and errors

Angular 21 uses signal-backed state with OnPush and no Zone.js. Camera info returned by GET /api/info appears in the Camera panel without manual change-detection calls. Connect reuses an existing matching link; if Node is down, the UI shows an error and unlocks buttons. The COM port is not opened on page load.

06 · Logs and API discovery

GET /api/help lists all ten Node routes. GET /api/logs?since=N streams incremental diagnostic events; POST /api/logs/clear clears the backend's 500-entry memory log. The UI provides a diagnostics tab/pop-out, search, filters, export and light/dark themes. Camera-info JSON can be logged, but JPEG binary data is not.
